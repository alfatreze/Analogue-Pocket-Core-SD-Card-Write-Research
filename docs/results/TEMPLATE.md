# Suite ID — descriptive title

[All results](README.md)

## Goal

State the question, expected capability, and conditions that define success.

## Method

Record setup/build/firmware/card identity, exact procedure, oracles, and evidence level. Distinguish simulation, fit/internal timing, immediate readback, cold recovery, and host remount.

## Corrections

Describe each failure or deviation, its cause when known, the change made, and how the correction was checked. Preserve failed evidence and identify any new revision. Write “None recorded” when applicable.

## Result details

Give the verdict, operation/session counts, actual bytes/hashes/errors, protection checks, evidence links, and remaining limits. Separate failed, inconclusive, completed, and pending cases.

### Case ID — descriptive title

**Goal:** The specific case hypothesis and required outcome.

**Method:** Exact actions, stopping boundary, and independent comparison.

**Corrections:** Changes or deviations during this case; “None recorded” if none.

**Result details:** Verdict, measurements, retained evidence, and limits. Do not infer unperformed checks from another case.

### Evidence and scope

Link the public structured reports and procedures; name retained local evidence when it is not published. Explain which wider capability remains unqualified.
